# MIPS OS

**MIPS 아키텍처의 교육용 MOS 프레임워크를 기반으로 운영체제의 핵심 동작을 구현·학습한 실험 저장소입니다.**

- 메모리 관리, 프로세스와 스케줄링, 시스템 콜·IPC, Copy-on-Write, 파일 시스템, 셸·파이프 코드를 포함합니다.
- 주 실행 대상은 **`70216005-lab6/`**입니다.
- 실험 소스와 테스트, 운영체제 구조를 정리한 한국어 문서를 함께 보관합니다.

## 주요 구성

| 영역 | 내용 | 확인할 파일·폴더 |
| --- | --- | --- |
| 부팅·예외 처리 | 커널 진입, 예외·인터럽트 처리 | `init/`, `kern/`, `include/asm/` |
| 메모리 관리 | 물리 페이지 할당, 페이지 테이블, TLB 관련 처리 | `kern/pmap.c`, `kern/tlb*` |
| 프로세스 | 실행 환경 생성·전환, 스케줄링 | `kern/env.c`, `kern/sched.c` |
| 시스템 콜·IPC | 커널 기능 호출, 프로세스 간 메시지·페이지 전달 | `kern/syscall*`, `user/lib/ipc.c` |
| Copy-on-Write | 공유 페이지의 쓰기 예외 처리와 지연 복사 | `user/lib/fork.c` |
| 파일 시스템 | 파일 서버, 블록 관리, 파일 요청·디스크립터 | `fs/`, `user/lib/fsipc.c`, `user/lib/fd.c` |
| 셸·파이프 | 프로그램 실행, 입력·출력 연결, 리다이렉션 | `user/sh.c`, `user/lib/spawn.c`, `user/lib/pipe.c` |

- 위 경로는 모두 `70216005-lab6/`를 기준으로 합니다.
- 수업 프레임워크와 실험 구현이 함께 포함되어 있으며, 소스의 기존 실험 안내 주석을 보존했습니다.

## 저장소 구성과 버전 구분

```text
MIPS_OS/
├── 70216005-lab6/         # 주 실험 코드: QEMU Malta / MIPS 4Kc
│   ├── init/             # 커널 진입과 초기화
│   ├── kern/             # 메모리·프로세스·시스템 콜
│   ├── include/          # 공통 헤더와 아키텍처 정의
│   ├── lib/              # 공통 라이브러리
│   ├── user/             # 사용자 프로그램·셸·라이브러리
│   ├── fs/               # 파일 시스템 서버
│   ├── tests/            # 실험별 테스트 구성
│   └── tools/            # 이미지·초기화 코드 생성 등 보조 도구
├── BUAA_OS/              # 원본 폴더에 있던 참고 코드: R3000 / GXemul
├── 70216008-lab6.zip      # 원본 폴더에 있던 별도 번호의 압축 자료
└── MIPS_정리버전.md       # 학습·구조 정리 문서
```

- `BUAA_OS/`는 원래 README의 작성자·블로그 안내를 보존한 참고 자료입니다. 아래 실행 안내는 `70216005-lab6/`에만 적용합니다.
- 정리 문서에는 다른 버전의 설명도 있으므로, 실행 환경과 상수는 주 실험 소스의 `Makefile`·`include.mk`·헤더를 기준으로 확인합니다.

## 실행 환경

| 항목 | 주 실험 코드의 설정 |
| --- | --- |
| 환경 | Linux 또는 필요한 도구를 설치한 WSL |
| 언어 | C (`gnu99`), MIPS 어셈블리 |

| 바이트 순서 | Little Endian (`-EL`) |

| 보조 도구 | GNU Make, 호스트 C 컴파일러 `cc`, Python 3, Linux 기본 명령어 |
| 디버깅 | `gdb-multiarch` (선택) |

## 빌드와 실행

현재 기본 `init.c`의 초기화·프로세스 생성 호출은 주석 처리되어 있습니다. **실험 테스트 구성이 초기화 코드를 생성하도록 빌드하는 경로**를 사용합니다.

### 셸 실험 구성

```sh
cd 70216005-lab6
make test lab=6_2
make run
```

- `tests/lab6_2/kernel.mk`는 사용자 초기 프로그램과 파일 시스템 서버를 지정합니다.
- `target/mos`와 파일 시스템 이미지 등 실행에 필요한 산출물은 빌드 과정에서 생성됩니다.
- 저장된 `.mos-this-lab` 값은 `6_0`이며 해당 테스트 폴더는 포함되어 있지 않습니다. 테스트 빌드 때 `lab=6_2`를 명시합니다.

### 파이프 실험 구성

```sh
make test lab=6_1
make run
```

- `tests/lab6_1/kernel.mk`에는 `testpipe`, `testpiperace` 등의 실행 대상이 지정되어 있습니다.
- `make test`는 선택한 구성으로 다시 빌드하는 작업입니다. 테스트 결과는 에뮬레이터의 콘솔 출력을 확인합니다.
- QEMU의 `-nographic` 화면은 `Ctrl+A`를 누른 뒤 `X`로 종료할 수 있습니다.

### 디버깅

```sh
# 테스트 구성으로 빌드한 다음 실행
make dbg
```

- 별도 터미널에서 직접 연결할 경우 `make dbg_run`을 실행하고, `gdb-multiarch target/mos`에서 `target remote localhost:1234`를 사용합니다.

## 확인 범위와 참고 사항

- 위 명령은 주 실험 코드의 Makefile과 실제 테스트 폴더를 대조해 작성했습니다.
- 업로드 작업을 수행한 Windows 환경에는 MIPS 교차 컴파일러와 QEMU가 없어, 커널 빌드·부팅·실험 테스트의 통과 여부는 확인하지 않았습니다.
- 주 실험 코드와 참고 코드의 CPU·에뮬레이터 설정이 다르므로 각 폴더의 설정을 사용해야 합니다.
- 원본 소스·문서·압축 자료를 보존하고, 기존 `.git` 메타데이터와 로컬 도구 설정·생성 파일은 업로드에서 제외했습니다.
